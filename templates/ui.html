Server Control

Actions that affect the entire running dnsbollocks process. See the Stats page for read-only engine statistics.

{{template "alert-banner" .}}

Reload Configuration

Re-reads config.json and the dependent rule/host/blocklist files from disk and applies them, without restarting the process — the WebUI equivalent of pressing Ctrl+R at the console. Listener settings that changed will be rebound.

Clear DNS Cache

Empties the internal DNS response cache immediately. Rules, hosts, and blocklists are left untouched.

Logout

Forces this browser to discard its cached WebUI login credentials by responding to this request with an HTTP 401 challenge. Your browser will very likely prompt for credentials again immediately afterward — cancel that prompt to actually remain logged out (entering the same password again simply logs back in). This is a limitation of HTTP Basic Auth, which has no server-side session to invalidate directly; see webui_auth_session_mode in config.json for related behavior.

Shutdown

Gracefully stops the running dnsbollocks process (all listeners close and the process exits). This is the only way to stop it when running headless (hide_console), where there's no console to press Ctrl+X in.

Any text or list setting below supports template strings that are dynamically evaluated at runtime. You can securely read sensitive parameters (like passwords, custom keys, or tokens) directly from the environment or external paths instead of exposing them raw in the configuration file:

  • {env:VARIABLE_NAME} – Pulls the value from a system environment variable named "VARIABLE_NAME".
  • {file:FILENAME} – Reads the content of an external text file named "FILENAME" that's next to the config.json file.
  • {builtin:clientexe} – Specific to "{{.UpstreamURLsKey}}" setting(key) only: Dynamically evaluates to the querying executable's name (useful for passing client attribution to services like NextDNS).
